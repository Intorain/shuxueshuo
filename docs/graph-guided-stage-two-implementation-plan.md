# 图谱交互课程阶段②实现计划：特征检查表判型与 D1、D2

> 状态：未实现。编写日期：2026-10-16；命中分流规则修订于 2026-10-17。
> 设计依据：[四阶段交互课程生成设计](graph-guided-interactive-lesson-design.md)第 5 节。
> 输入依据：[阶段①实现计划](graph-guided-stage-one-implementation-plan.md)。阶段②读取阶段①已经验收的题意和特征，不再识图、不再提取题意。
> 命中规则：唯一命中 → 程序确认；多个命中（一律）→ LLM 选定；未命中 → 不调用 LLM，学生端暂不支持，本地文件待处理（数据库待前后端打通）。
> 判型单位：阶段①的每个目标（`target_ref`），即每个小问独立判型、点亮知识点、出 D1/D2。

## 1. 目标与边界

程序用特征检查表缩小题型范围；唯一命中则确认，多个命中交 LLM，未命中则对学生说暂不支持并落本地待处理记录。归属确定后生成 D1、D2。

**判型单位是目标，不是整题。** 阶段①按目标输出特征，多问题的每个小问各有一组 `target_ref` 相同的特征。阶段②把这组特征当作一道独立的题来做全部检查、命中分流、知识点点亮和 D1/D2；同一题的不同小问可以属于不同题型，也可以一问支持、一问暂不支持。单问题只有 `/root/goals/0` 一个目标。D1 的片段定位只在该小问的题面段落及题干共用部分中进行。

```text
阶段①结果（candidate + features）
→ 程序按识别契约检查全部已登记题型
→ 恰好一个得到支持：程序确认主要归属
→ 两个及以上得到支持：LLM 在候选中选定主要归属
→ 零个得到支持：不调用 LLM；学生端「暂不支持」；写入本地待处理记录
→ 归属已定时，程序生成 D1、D2
```

本阶段做：

- 三份识别契约：`type-quantified-quadratic`、`type-parameter-quadratic-solve`、`type-amgm-quantified`。
- 对每个题型的每个分支做三态检查，保留被排除的候选和依据。
- 唯一命中 / 多命中 / 未命中三条路径；多命中录制 LLM 选择；未命中落本地文件。
- 从 `original_text` 定位 D1 可点选片段；定位不到就不提供该选项。
- 用得到支持的题型和节点上的 `confuse` 生成 D2（仅归属已定时）。
- 以阶段①录制的 22 个真实候选（11 题，含 2 道多问题）作为测试输入，离线重放结构判定，不再请求视觉模型。

本阶段不做：选法、求解、方法前提检查、课程步骤、WebSocket、未命中记录的数据库表（与前端打通时再做）。知识点反向的“涉及”关系只给 D1 展示候选，不参与归属。题型规模只有三份契约，直接遍历，不做倒排索引。

## 2. 输入

正常输入是阶段①的 `stage-one-result.json` 中这两块：

| 字段 | 用途 |
| --- | --- |
| `candidate.original_text` | D1 片段定位与展示 |
| `candidate.root` | 仅在按需验证时读取量词关系；结构判型不重新解析题意 |
| `features[]` | 判型唯一的结构证据。按 `target_ref` 分组，每组读取 `feature_id`、`status`、`value`。`calculation`、`diagnostics` 不参与匹配 |

`status` 不是 `known` 的特征，对应检查为未知，不能当成不成立。

测试输入分两路，都不再识图：

- 确定性测试：11 题 `notation.gold.json` 经现有 `extract_features` 得到特征，再判型。
- 录制回放：`recorded/live-v2-20261017-02` 的 22 个真实候选。先用阶段①验收确认题意和特征仍然通过，再跑阶段②。视觉模型调用次数为 0。

## 3. 识别契约

契约放在 `site/data/knowledge-next/recognition/`，一题型一份，题型 ID 与节点 ID 相同。不写进节点 JSON，避免学生页契约和判型规则混在一起。

每份契约：

| 字段 | 要求 |
| --- | --- |
| `type_id` | 已有题型节点 |
| `branches[]` | 分支 ID、必要条件、排除条件。任一分支通过即支持该题型 |
| `checks[]` | 只比较阶段①已有特征的 `status` 和 `value`，不写表达式模式 |
| `student_cue` | 指向该题型节点 `features` 里的一条已有线索，供 D2 展示 |

不设 `direct` / `alternative` 角色：凡得到支持的题型都计入命中集合；命中个数决定是否调用 LLM。

`type-quantified-quadratic` 两个分支：

| 分支 | 必要条件 |
| --- | --- |
| 量词变量的二次式 | `quantifier` 为 ∀ 或 ∃；`goal.kind` 为 `find_range`；`relation.operator` 为 `<`、`<=`、`>`、`>=` 之一；`degree_in_bound` 为 `exact` 且次数为 2，或为 `upper_bound` 且上界恰为 2（含参二次项系数可能为 0） |
| 更换主元 | 同样的量词、目标和不等号要求；`degree_in_goal.degree` 为 2；`degree_in_bound.degree` ≤ 1；`range_var_is_principal` 为假 |

上界为 1 或 0 的含参式（如 `∀x∈ℝ: a·x+1≥0`）不是二次式；`=`、`!=` 关系（如 `∃x∈ℝ: x²=a`）是方程或不等于条件，不属于恒成立、有解的不等式题。两个分支都按冲突处理，测试各用这两个反例覆盖。

`type-parameter-quadratic-solve`：必要条件是目标为求解集且系数含参；排除条件是 `quantifier` 存在。Q01–Q09 的目标都是 `find_range` 且带量词，该题型冲突。

`type-amgm-quantified`：结构前提是量词存在且目标为求范围。和积结构不是阶段①特征，由第 5 节的按需验证给出；验证不可用时这项为未知，不支持也不排除。二次结构不作为它的排除条件。

节点 `features` 里“通常转化为最值”这类方法提示不写入契约。

九题的结构命中（验证前）：

| 题目 | 通过的分支 | 含参求解 | 基本不等式（验证前） |
| --- | --- | --- | --- |
| Q01–Q03、Q06 | 量词变量的二次式 | 冲突 | 未知（未验证）→ 仅恒成立唯一命中 |
| Q04、Q05、Q07 | 量词变量的二次式 | 冲突 | 未知 → 仅恒成立唯一命中 |
| Q08、Q09 | 更换主元 | 冲突 | 未知 → 仅恒成立唯一命中 |

两道多问题按小问判定：

| 小问 | 通过的分支 | 含参求解 | 结论 |
| --- | --- | --- | --- |
| Q10（1） | 量词变量的二次式（∀，ℝ） | 冲突 | 恒成立唯一命中 |
| Q10（2） | 量词变量的二次式（∃，[1,2]） | 冲突 | 恒成立唯一命中 |
| Q11（1） | 无：阶段①对不含量词的关系不计算结构特征，相关检查均为未知 | 未知 | 未命中，该小问暂不支持并落待处理记录 |
| Q11（2） | 量词变量的二次式（∀，[1,3]，首项系数含参） | 冲突 | 恒成立唯一命中 |

Q11（1）是有意保留的缺口：要支持它，需要在阶段①特征注册表中为不含量词的关系增加特征，并补上含参求解的识别契约；数据结构不变。

Q01 在第 5 节验证通过后，恒成立与基本不等式**同时得到支持**，进入多命中，须调用 LLM；预期 LLM 选定 `type-quantified-quadratic` 为主要归属。验证未通过时仍为唯一命中，不调用 LLM。

## 4. 判定

程序对每份契约的每个分支评估全部检查：

1. 读取的特征不是 `known`，该检查为未知。
2. 分支的必要条件全满足、排除条件全不成立，分支得到支持。
3. 必要条件冲突或排除条件成立，分支冲突。
4. 其余情况，分支未知。
5. 题型的任一分支得到支持，题型得到支持。全部分支冲突，题型冲突。否则题型未知。

主要归属按命中个数：

| 得到支持的题型数 | 程序行为 | LLM | 学生端 |
| --- | --- | --- | --- |
| 1 | 确认为主要归属；来源 `program` | 不调用 | 正常 D1、D2 |
| ≥ 2 | 把候选与检查报告交给 LLM；来源 `llm` | 必须在候选中选一，引用检查 ID；不能翻案冲突项，不能引入候选外题型 | LLM 选定后出 D1、D2；未选中的支持题型标为替代思路 |
| 0 | 未命中；来源 `unsupported` | 不调用 | 「当前暂不支持该题型」；不出 D2 |

**未命中记录（本阶段用本地文件）**

写入 `internal/solver-runs/graph-guided-stage-two/unsupported/<run-id>/`（gitignore 目录），每条至少含：题意摘要或 `candidate` 引用、特征表、全部检查结论、时间戳、运行 ID。不建数据库表；与前端打通时再迁库并做后台列表。

验证关闭时，九道单问和 Q10、Q11（2）预期全部唯一命中、0 次 LLM；Q11（1）为真实的未命中样例。Q01 验证打开后预期 1 次 LLM。多命中 LLM 路径另用构造样例测。未命中记录按小问写入，记录中带 `target_ref` 和小问编号。

## 5. 基本不等式的按需验证

只验证“这条量词关系能否经恒等变形，变成可用基本不等式求界的和积结构”。不生成方法轨迹，不求参数范围。验证能力以后与阶段③共用；本阶段只接 Q01 这一处。

Q01 的预期证据固定为：$-x^2+2x+3=3+x(2-x)$；在 $0<x<2$ 上 $x+(2-x)=2$，故 $x(2-x)\le 1$，等号在 $x=1$ 取得；在其余实数上该积不大于 0。从而全实数上的最大值为 4。验证器必须给出这些步骤的可检查记录。做不到时返回未知及原因；此时不因「未知」去调用 LLM（仍可能因唯一命中恒成立而不调用）。

验证通过后 Q01 变为双命中，**必须**走 LLM 选定主归属；验收时期望选定恒成立。

Q02–Q09 不要求找出和积结构。验证器对它们返回未知是允许的，不影响唯一命中。

现有求解器里的基本不等式代码服务的是另一批题目，不直接搬来搜二次式。Q01 这一处写明确的有界变形和前提检查，不做成通用不等式搜索。

## 6. 由特征值取知识点

D1 要回答“这句话对应哪条知识”，图谱要点亮知识再连到题型，所以阶段②同步给出每个目标的知识点。**知识点只由特征值推出，不由判定出的题型反推**：学生先在 D1 认知识、再在 D2 选题型，若用题型反推知识点，D1 就成了拿 D2 的答案倒推；题型节点的 `knowledge` 是这一类题的通用清单，其中如“最值”属于选法内容，提前点亮会泄露方法；未命中时题型不存在，知识点仍需展示并写进待处理记录。

阶段①特征上的 `knowledge_refs` 是按特征静态登记的“可能关联”，与取值无关（例如 `quantifier` 同时挂全称和存在）。阶段②改用一份按值取用的规则表 `site/data/knowledge-next/recognition/feature-knowledge.json`，每条规则写明特征、取值条件和点亮的知识条目。首批规则：

| 特征与取值 | 点亮的知识条目 |
| --- | --- |
| `quantifier` 为 ∀ | `quantifiers#universal` |
| `quantifier` 为 ∃ | `quantifiers#existential` |
| `bound_vars`、`free_vars`、`goal` 均为 `known` | `quantifiers#roles` |
| `domain` 为 `known` | `quantifiers#domain` |
| `relation.operator` 为 `<`、`<=`、`>`、`>=` 之一，且 `degree_in_bound` 或 `degree_in_goal` 为 2，或含参且上界为 2 | `quadratic-inequality#definition` |
| `degree_in_bound` 为 2，或含参且上界为 2 | `quadratic-function-properties#definition` |

二次不等式定义必须同时满足关系符与次数两项：只看次数会把二次方程当成二次不等式，例如合法输入“∃x∈ℝ:x²=a，求 a”的次数特征为 2、`relation.operator` 为 `=`，不点亮二次不等式定义；`relation` 为 `unknown` 时同样不点亮。二次函数性质只看关于量词变量的次数，不看关系符：上例要用 x² 的值域，仍点亮二次函数性质。

规则只读 `status=known` 的特征；`unknown` 不点亮任何知识，也不报错。`degree_in_bound` 为 1 时不点亮二次相关条目（Q08、Q09 关于量词变量是一次式，关于目标变量才是二次，因此只点亮二次不等式定义）。一次函数区间最值、函数最值、判别式等属于选法与步骤的知识，不在 D1 规则中，留给阶段③。规则表的知识引用由测试检查存在于图谱。

点亮结果用于三处：

1. **D1 片段**：每个片段经 `source_refs` 找到它支撑的特征，再挂上这些特征点亮的知识条目。
2. **知识到题型的连线**：主要归属确定后，取“本题点亮的知识”（按节点 ID）与该题型 `knowledge` 的交集，在图谱上画出知识 → 题型的高亮线，对应 Demo 中由知识连到题型的那一步。交集外、只在题型清单里的知识（如 Q01 的 `function-range-extrema`）D1、D2 不点亮，留到 D3。
3. **诊断**：交集为空或明显偏小时写入报告，提示契约或规则表可能有缺口；不改变判型结论。

九题的预期：Q01–Q04、Q06、Q07 点亮 `quantifiers#universal`、`#roles`、`#domain`、`quadratic-inequality#definition`、`quadratic-function-properties#definition`；Q05 将全称换为 `quantifiers#existential`；Q08、Q09 点亮 `quantifiers#universal`、`#roles`、`#domain`、`quadratic-inequality#definition`，不点亮二次函数性质。多问题按小问：Q10（1）、Q11（2）同 Q01 一组，Q10（2）同 Q05 一组；Q11（1）的结构特征均为未知，不点亮任何知识，未命中记录中知识点为空。

## 7. D1、D2

仅在主要归属已确定（程序或 LLM）时生成；未命中时跳过 D2，D1 可仍展示题面线索供调试，但不作为学生判型题。

D1 在 `original_text` 上定位片段。阶段①只保证转录与题源在“版式、TeX 拼写、叙述标点”之外一致（见阶段①评估的 `normalized_transcription`），不保证公式带 `$`；真实批次中 Q06/sample-02 的转录就是 `“∀x<0，x^2+ax+2≥0”为真命题，…`。因此 D1 的公式定位不依赖 `$`：

- 公式候选区间：有 `$...$` 时取定界内文本；其余部分按公式字符游程切分，即 ASCII 字母数字与 `()[]{}+-*/^=<>|∞ℝ∈≤≥∀∃_'` 及夹在两个公式字符之间的 `.,;:` 组成的最长连续段（与转录比较中保留数学标点的规则相同）。全角标点、汉字和空白之外的叙述字符结束一个游程。
- 每个候选区间先做与转录比较相同的显示归一（TeX 命令转 Unicode、去 `\text{}`、花括号转圆括号），一个游程可能含多个片段（如 `∀x<0,x^2+ax+2≥0`），按顶层 `,`、`:` 再切一次。
- 题面公式按教材写法书写，与标准题意不同：`ax`、`mx` 是隐式乘法，`y<0`、`f(x)≥0` 引用题面里的别名或函数定义，而标准题意里乘号已显式、别名已展开（Q08/Q09 不保留 `y=…`）。因此片段不送现有记法解析器，而是经下面的题面读法转成代数式，再与特征值比较：
  1. **符号上下文**：取该目标的 `free_vars` 与 `bound_vars` 作为已知单字母变量。字母串若本身不是已知名、别名或函数名，且每个字母都是已知变量，则拆成乘积（`ax`→`a·x`、`kx`→`k·x`）；否则保留为一个名字，交由后续步骤判定。数字后接字母或括号、`)` 后接字母数字或括号都补乘号。
  2. **题面别名与函数**：同一目标可见的题面片段中，形如 `y=表达式`（`y` 不是已知变量）的记为别名，形如 `f(x)=表达式` 的记为单参函数；按题面顺序登记，后出现的片段可引用先登记的。关系片段中的别名直接代入，函数调用按实参代入函数体。
  3. **比较**：关系片段按顶层唯一的比较符拆成左右两边，算出“左−右”，与 `relation` 特征的“lhs−rhs”比较；比较符相同时差为零、或比较符方向相反时差的相反数为零即命中（`expand` 后判零，不做近似数值判断）。以 `∀`、`∃` 开头的量词前缀片段不作关系比较，交给量词词表与 `domain` 匹配。
  4. 任一步无法处理（未知名字、多个比较符、函数未登记等）只让该片段不成为选项，不报错。
- 用阶段①录制 `live-v2-20261017-02` 的 22 个候选做过离线可行性检查：按上述读法，24 个目标的关系特征都在各自题面上定位到片段，包括 Q06 的 `x^2+ax+2≥0`（含无 `$` 的 sample-02）、Q08 的 `y<0`、Q09 的 `y>0`、Q10 两问的 `f(x)≥0` 与 `f(x)<0`、Q11（2）的 `f(x)<-m+5`。实现时把这 24 个定位结果写成金标测试。
- 量词和目标措辞用固定词表：任意、所有、恒成立、存在、有解、取值范围。
- 命中的片段带上第 6 节点亮的知识条目。
- 对不上任何特征的叙述片段才可作为干扰项。Q01 的“实数”是有效信息，不做干扰项。
- 某个线索定位不到就省略该选项，阶段②仍算完成。

D2 的选项是得到支持的题型，加上这些题型 `confuse` 里、并且本轮契约已经评估过的易混题型。反馈用节点上的 `confuse.text`。被判冲突的选项是错误候选；得到支持但不是主要归属的选项标明替代思路，不能写成数学错误。

Q01 的 D2 与 [Demo 设计](graph-walk-demo-q01-design.md) 一致：主要题型为恒成立，含参求解为错误候选；基本不等式在验证并经 LLM 选定主归属后，作为未选中的支持题型标为替代思路。验证尚未通过时，基本不等式不进入选项，也不写成错误。

## 8. 输出

`graph-stage-two-result/v1` 顶层含运行 ID、阶段①结果引用和 `goals[]`。`goals[]` 按题面顺序，每项对应一个目标，带 `target_ref`、小问编号以及下列字段：

| 字段 | 内容 |
| --- | --- |
| `knowledge` | 点亮的知识条目，每条带触发它的特征与取值；与主要归属的交集及连线 |
| `types` | 每份契约的结论、通过或冲突的分支、逐项检查 |
| `primary` | 主要归属；未命中时为 `null` |
| `primary_source` | `program` / `llm` / `unsupported` |
| `supported` | 全部得到支持的题型 ID（含未选中的） |
| `d1` / `d2` | 片段；未命中时 `d2` 为空 |
| `verification` | 按需验证的输入、步骤和结论；未运行则说明原因 |
| `llm` | 本目标的调用次数、候选列表、选择依据；唯一命中与未命中路径为空。顶层另汇总全题调用次数 |
| `unsupported_record` | 未命中时本地记录路径；否则省略 |

调试报告沿用阶段①的离线 HTML：题图、特征、点亮的知识及触发依据、每份契约的检查、命中路径、D1 高亮、D2 选项、未命中记录入口。不新增出处金标。

## 10. 实施顺序

1. 契约和检查执行器，按目标分组，用 11 题金标特征做通唯一命中与 Q11（1）未命中路径。
2. 接入 22 个阶段①录制候选（验证关闭），确认各目标主要归属一致且无网络调用。
3. 未命中落盘与学生端「暂不支持」状态。
4. 特征值到知识点的规则表与知识 → 题型连线。
5. D1 定位和 D2 选项，先对照 Q01 Demo，再覆盖 Q02–Q09。
6. Q01 的和积验证；通过后走多命中 LLM，录制选择并做零网络回放。
7. 再构造一份非 Q01 的多命中样例，确认「一律交 LLM」不依赖基本不等式特例。
