# 图谱解题过程 Demo 技术设计：恒成立 Q01

> 状态：已实现，2026-10-14 完成本地集成。使用与验收见 [Demo 维护说明](graph-walk-demo-q01.md)。
> 题目：`/2/q01/`（`quadratic-always-q01`）。公共图谱原稿：`site/data/knowledge-next/`，正式入口：`/knowledge/`。
> 相关设计：[公共知识图谱设计](public-knowledge-graph-ontology-design.md)、[Method Solver 当前架构](method-solver-architecture.md)、[交互题目公共运行时设计](interactive-lesson-shared-runtime-design.md)。

## 1. 目标与边界

用恒成立 Q01 演示“沿图谱选择并执行解题路径”：识别知识线索 → 筛选题型 → 经过规则选择方法 → 调用技能或子方法 → 得到答案。学生每次提交后，图谱显示对应的节点、调用和依据，并记录本次遍历结果。

学生界面和 LLM 作答者共用决策点、回答格式与状态推导。Demo 用于检查图谱能提供哪些候选和路径，以及哪些数学判断仍需要作答者完成。

- 复用现有数学题目表达、公共图谱和 Q01 教学交互，不另建题目事实模型。
- 首批贯通判别式法、分离参数法两条路线；其他方法可以作为候选展示，不能因尚未实现交互就判为数学上不可用。
- 不修改正式 Q01 的交互、导师和学习记录；Demo 不保存个人学习记录。
- 不接入生产 Solver，不生成 FunctionalPlan，不建设通用谓词引擎。候选遍历是真实图计算，首批判断与反馈由人工编写，页面明确标注。

## 2. 输入：直接复用现有数学表达

原题：若不等式 $-x^2+2x+3\le a^2-3a$ 对任意实数 $x$ 恒成立，求实数 $a$ 的取值范围。

### 2.1 现有来源与缺口

| 内容 | 现有来源 | Demo 使用方式 |
| --- | --- | --- |
| 原题文字、条件、目标 | `server/shuxueshuo_server/tutor_demo/lessons/quadratic-always-q01.json` 的 `problem.statement/conditions/target` | 核对原题，保留原文展示 |
| 数学表达格式 | `internal/schemas/problem-math-notation-v1.schema.json`（`problem-math-notation/v1`） | 复用 `root.facts`、`root.goals` 及现有作用域结构 |
| 表达校验与编译 | `server/shuxueshuo_server/problem_understanding/notation_compile.py` 的 `NotationValidator.validate()` | 使用 `report.normalized`、`report.semantic` 和已有来源位置 |
| 公共节点与关系 | `site/data/knowledge-next/`，现有 `loadSources()`、`deriveEdges()` | 生成候选、方法步骤、调用及数学依据 |
| Q01 交互与完成态 | `site/2/q01/index.html` 的 `practice-config`、`template`，以及对应教师 JSON | 构建时提取并校验，保留路线和步骤 ID |

数学输入已补录于 `site/data/math-notation-v1/quadratic-always/q01.json`，通过现有校验与编译，由 Demo 引用。`math-notation-v1/basic-inequality/q01.json` 是另一道题，不能混用。

本题的数学正文可表示为以下内容；这里只展示现有格式中的 `root`，完整文件仍遵守既有契约：

```json
{
  "root": {
    "facts": ["a∈ℝ", "∀x∈ℝ: -x^2+2*x+3 ≤ a^2-3*a"],
    "goals": [{"kind": "find_range", "symbol": "a"}]
  }
}
```

原格式中的 `facts` 是题设数学字符串数组，直接沿用即可。Demo 不再创建 `f.quantifier`、`f.degree`、`f.leading` 等对象，也不复制维护一份量词、次数和系数表。

`basic_inequality_problem_ir.py` 的转换器目前不接受量词结构。本 Demo 直接使用 notation 编译结果，不把本题强行转换成基本不等式的 ProblemIR，也不引入整套生产 Solver。

### 2.2 判断时读取，执行后保留结果

| 所需信息 | 如何取得 |
| --- | --- |
| 量词、变量范围、原不等式、求解目标 | 读取现有数学表达及其编译结果 |
| 关于 $x$ 的次数、首项系数、参数是否已分离 | 在当前决策点由学生或 LLM 判断；需要确定性计算时复用表达解析结果 |
| 整理后的不等式、最大值、参数范围 | 对应步骤通过后保留为中间结果，不能提前当作题设提供 |
| 判断理由 | 自然语言说明；需要定位时引用原表达路径或已通过的步骤结果 |

来源定位使用题目 ID、表达版本和现有字段路径（例如编译器的 `r.facts[1]`）。路径与版本一起保存，防止整理稿调整数组顺序后引用错位。无需新增事实 ID 或事实管理界面。

题目表达可能携带既有抽取流程的 `family_id` 等匹配信息，它不是本 Demo 的题型答案，也不用于预先选定公共题型；给学生和 LLM 的输入只投影原题数学内容。

## 3. Demo 保留的数据

| 对象 | 最小职责 |
| --- | --- |
| 题目引用 | 指向现有数学表达及版本 |
| 决策点 | 当前问题、候选来源、交互形式、判定与反馈 |
| 作答记录 | 学生或 LLM 的原始回答、判定结果、所属路线运行 |
| 中间结果 | 某个已通过步骤的结果及来源；随撤销和换路线更新 |
| 执行记录 | 本次实际选择的分支、调用发生在哪个方法步骤、实际用到哪些依据 |

图谱状态由输入快照和作答记录推导；不在点击事件里直接维护另一套节点状态。错误回答保留反馈，但不推进路径、不产生已确认结果。

候选需分别表达三件事：**适用性、推荐理由、是否已有 Demo 交互**。适用性可为“可用／不满足条件／待判断”；推荐优先级和实现范围不能冒充适用性。

## 4. Q01 决策与执行路径

### 4.1 公共决策

| 决策 | 交互 | 图谱操作 |
| --- | --- | --- |
| D1 读题 | 逐句判断题意 | 点亮知识点，反查涉及这些知识的题型 |
| D2 确定题型 | 选择最直接描述本题条件与目标的题型 | 确认主要题型，显示易混题型及区别 |
| D3 选择解题方法 | 在方法坐标图中点选本题所在格，再选这一格里的一种方法 | 展开 `rule-quadratic-method` 的四个分支，确认路线并展开方法步骤 |
| 后续步骤 | 复用 Q01 的点选、清单、填空 | 记录实际调用，显示本步结果与依据 |
| 完成 | 查看路径，或换另一种方法 | 汇总实际执行过程 |

D1 至 D3 是 Demo 自有决策，不要求它们出现在正式题页的步骤列表中。

### 4.2 D1、D2：知识线索与题型

“对任意实数 $x$ 恒成立”对应 `quantifiers#universal`；原不等式关于 $x$ 的二次结构对应 `quadratic-inequality`；“求 $a$ 的取值范围”用于区分求参数与求 $x$ 的解集。原题中的实数条件仍是有效信息，不把它设置成“不是解题线索”的错误选项。

从前两个知识点反向遍历 `involves`，按知识覆盖数排序。当前数据得到 6 个候选：`type-quantified-quadratic` 覆盖两条线索，其余 5 个各覆盖一条。数量由图谱计算；Q01 测试保存候选快照，日常构建不硬编码数量。

D2 展示最高覆盖候选及其 `confuse` 字段列出的易混题型：

| 候选 | 本题中的判断 |
| --- | --- |
| `type-quantified-quadratic` 含参一元二次不等式的恒成立与存在成立问题 | 最直接的主要题型：对所有 $x$ 成立，求 $a$ 的范围 |
| `type-parameter-quadratic-solve` 含参数的一元二次不等式求解问题 | 不符合当前求解目标；该任务通常给定参数讨论 $x$ 的解集 |
| `type-amgm-quantified` 应用基本不等式的恒成立与存在成立问题 | 需要额外变形，可作为替代思路；不能仅因原式为二次式就断言基本不等式不可用 |

例如 $-x^2+2x+3=3+x(2-x)$，在 $0<x<2$ 时可用基本不等式，在其余范围可直接判积的符号，仍能得到最大值 $4$。此路线不在首批完整交互范围内。

图计算给出相关候选，不能仅凭“涉及同一知识点”就确定题型。D2 判断的是主要任务；更间接的有效解法不作为数学错答处理。

### 4.3 D3：方法坐标图与演示范围

由题型沿 `method_rule` 进入 `rule-quadratic-method`，再展开 `selects`：

| 方法 | 本题判断 | Demo 安排 |
| --- | --- | --- |
| 判别式法 | 可用；$x\in\mathbb R$，关于 $x$ 的二次项系数确定非零 | 完整路线，页面 ID `discriminant` |
| 分离参数法 | 可用；原式已将 $a$ 与 $x$ 分离，无需除以含变量的式子 | 完整路线，页面 ID `extremum` |
| 区间最值法 | 数学上可行但被取代（`superseded`）；$\mathbb R$ 也是区间，但 $x$ 取全体实数时判别式法更直接 | 坐标图中只覆盖“$x$ 在某个区间、参数无给定范围”一格，本题格不列出 |
| 更换主元法 | 当前规则条件未触发；量词变量 $x$ 已是所考察的主元 | 不推荐为本题入口；不宣称任何换元思路都无效 |

区间分支已明确包含全体实数 $\mathbb R$，适用条件与推荐理由分别表述。

D3 用 2×2 坐标图代替逐条阅读分支条件：横轴“$x$ 取全体实数吗？”，纵轴“参数有给定范围吗？”。每个分支在原稿 `coverage` 中登记覆盖的格子；坐标图表达的是“这一格推荐用哪些方法”，不是“数学上哪些方法可行”：构建时校验本题所在格覆盖的方法恰好是判为 `fit` 的分支，被更直接方法取代的分支判为 `superseded` 并不出现在本格，同时把已实现路线绑定到对应分支。作答为 `[横轴, 纵轴, 方法]`：先逐轴判断格子，再判断方法是否在这一格里；若本格有未实现的方法，返回“有效思路 · 本 Demo 未展开”，不伪装成错误选择。选中已实现的方法即开始该路线。

### 4.4 判别式路线

页面路线 `discriminant` 对应 `method-discriminant`。下表为与公共原稿核对后的实际映射：

| 页面步骤 | 方法步骤 | 本题操作／调用 |
| --- | --- | --- |
| `d_basis` | `degree` | Demo 中省略（原稿 `omit`）：$x$ 的范围已由 D3 坐标图确定，题页仍保留此步 |
| `d_rewrite` | 新增 `normalize` | 不等式变形与化简，得到 $x^2-2x+a^2-3a-3\ge0$ |
| `d_position` | `conditions` | 调用 `skill-quadratic-sign`，判断图像不低于 $x$ 轴；Demo 用原稿 `present` 改为图形多选（相切、穿过、不相交，选出全部满足的），完成卡片仍用题页模板 |
| `d_delta` | `conditions` | 建立 $\Delta\le0$，化为 $a^2-3a-4\ge0$；记录实际化简调用 |
| `d_range` | `solve` | 调用子方法 `quadratic-inequality-solve`，得 $a\le-1$ 或 $a\ge4$；Demo 用 `present` 改为图形单选：同一条 $h(a)$ 图像，横轴上分别标出两根之间、两根外侧（空心端点）、两根外侧（实心端点），图下不写范围 |
| `d_boundary` | `merge` | 回代检查 $a=-1,4$；两端均保留 |

一次教学步骤可以覆盖多个模板操作；一个模板步骤也可以在多个教学步骤中执行。映射记录实际调用位置，不强求一对一。

### 4.5 分离参数路线

页面路线 `extremum` 对应 `method-separation`，保留原路线 ID。

| 页面步骤 | 方法步骤 | 本题操作／调用 |
| --- | --- | --- |
| `e_basis` | `separate` | 确认原式已经分离，本步不调用变形技能；Demo 用 `present` 改为“分离参数法适用地图”：与选方法同样的十字坐标，横轴“参数能否单独放到一边”（分不开 / 能分离）、纵轴“是否要除以含 $x$ 的式子”（要除 / 不用除），四格标所属区域（直接比较最值、先定符号再除、不适用），点出本题一格，逐轴给反馈；完成卡片显示钉住本题的同一张地图，加题页的完整推导 |
| `e_condition` | `quantifier` | 调用 `skill-quantified-range`，转成 $a^2-3a\ge\max_{x\in\mathbb R}(-x^2+2x+3)$ |
| `e_extremum` | `range` | 调用子方法 `method-square-extremum`，其中 `square` 步调用技能 `method-complete-square`；得到 $4-(x-1)^2$，最大值为 $4$，在 $x=1$ 取到 |
| `e_range` | `restore` | 调用子方法 `quadratic-inequality-solve`，解 $a^2-3a-4\ge0$；Demo 用 `present` 改为与 `d_range` 相同的三张 $h(a)$ 图形单选，题干先接上 $a^2-3a\ge4$ |
| `e_boundary` | `restore` | 回代验证边界和原恒成立条件 |

路线走完后，Demo 不再套用题页的完成卡（那张卡同时总结两种方法），而是显示自己的短卡：已走过的路线名、答案、本路线一句要点（原稿 `routes.*.takeaway`），以及“再用另一种方法做一遍”和返回题库链接。答案写在原稿 `completion.answer`，构建时校验它与题页完成卡一致。

这里保留真实的“配方求最值法 → 配方技能”。不为迁就当前图谱调用表，把配方过程改标成“根据顶点求二次函数区间最值”。后者仍是可选解法。

首批不新增 `e_skill` 三选一题：函数类型不能唯一决定算法，配方与顶点法均可行。需要演示方法内部选路时，后续可增加独立的 Demo 决策，从真实候选调用中选择，并分别说明适用性与实现范围。

子方法默认折叠展示，展开后显示本次实际执行的步骤。配方方法的消元、换元等准备调用在本题未发生，不计入执行轨迹。

## 5. 图谱计算与执行记录

### 5.1 关系方向

| 查询／展示 | 约定 |
| --- | --- |
| 从知识反查题型 | 沿 `involves` 反向查询；真实箭头仍为“题型 → 知识点” |
| 题型选择方法 | `题型 → 选法规则 → 方法`；遵守图谱登记的关系 |
| 方法执行 | 按 `steps` 的次序展示，以 `calls`、`step_rule` 和规则分支作为候选来源 |
| 技能依据 | 通过 `uses` 及条目引用定位知识；只突出本次实际使用部分 |
| 易混题型 | 来自 `confuse` 字段，用辅助点线表示，不当作图谱关系 |
| 错选反馈 | 标示尝试的候选和反馈；没有真实关系时不伪造一条图谱边 |

构建期从真实图谱提取候选、子图和固定布局，浏览器按当前作答执行选择、调用记录和汇总。日志分别标注“图谱查询”“作答判断”“执行结果”，不把手写适用性结论称为图计算结果。

### 5.2 按实际调用汇总

每次调用记录路线运行 ID、教学步骤、方法及模板步骤、调用目标，以及本次使用的知识条目。引用必须存在于真实模板及技能依据中；公共原稿缺少的关系先补齐，不能依赖 Demo 白名单绕过校验。

概览图可合并同一对节点的重复连线，执行记录必须保留各次 occurrence。例如某技能在“分离”和“还原”两步被调用，是两次记录；跳过前一次不能把后一次也置灰。

“实际用到的知识”只汇总本次执行记录中已确认的依据，不能递归收集子方法全部候选技能的 `basis`。技能登记了多个依据，也不代表本题全部用过。边界验证可以保留为文字操作；没有实际技能调用时不虚构 `uses` 边。

### 5.3 后退与换路线

- 后退后重新推导状态，移除被撤销步骤及依赖它的后续调用和结果。
- 换方法时新建路线运行，并把 D3 改记为新路线对应的方法；原题输入与 D1、D2 可复用；上一条路线的中间结果不进入新路线的判断输入。
- 已完成路线可另色叠加用于比较，但不参与当前路线的判定。回放绑定同一份输入快照。

不新建一份 Demo 数学 schema。中间结果复用已有数学字符串表示和步骤来源；Demo 原稿仅维护展示与决策需要的附加信息。

每个决策标明来源：`page` 引用正式题页的路线与步骤；`authored` 是 D1–D3 等 Demo 自有交互。前者必须与题页配置及教师契约一致，后者在 Demo 中校验，不要求向正式题页添加步骤。

构建期提取 `practice-config` 及所需模板，作为生成快照写入 bundle。浏览器不再临时抓取 `/2/q01/` 的最新模板。Bundle 版本覆盖数学输入、公共图谱、Demo 原稿、题页配置与模板；只记录公共图谱版本不足以绑定这次演示。

命令提供 `--check`：只读取、校验和比较，不写文件。至少检查：

- 表达通过既有校验；节点、条目、分支、页面步骤和模板引用有效。
- 每个交互候选都有判定说明；允许“待判断”，但必须提供下一步说明，不能默认为不适用。
- 所有实际调用都在对应模板登记，依据属于实际调用技能；重复调用保留发生位置。
- 决策可达，只有通过的步骤可以释放结果；答案、反馈和路线结论不进入作答者的待答输入。
- 同样输入生成同样产物；缺失或过期产物使 `--check` 失败。

## 8. 页面与作答者

入口：`/lab/graph-walk/quadratic-always-q01/`。默认不进入题库导航，不连接导师或学习记录；是否发布在验收后决定。

桌面左侧显示原题、当前问题、已完成步骤，右侧显示固定位置的子图与计算日志。已有结果直接显示在完成步骤中，不增加“事实面板”。

手机按用法分两种布局。看 AI 解题时是播放器：图谱铺满屏幕，上方一行原题，图谱下方是字幕、时间轴和播放键；步骤卡片收在底部抽屉里，点“步骤详情”弹出，回放推进时只滚动抽屉，不移动图谱。自己做时步骤卡片仍在页面上，路径条下方固定一条实时小图谱，提交后可看到图谱生长；小图谱不接收手势，点一下展开为全屏图谱。手机打开时直接进入看 AI 解题的播放器，停在起点，按 ▶ 才开始播放；图谱一律从 3D 开始，镜头跟随当前步骤。

子图按“知识线索／题型／规则／方法／技能与子方法／依据条目”布局。依据条目可以作为展示定位点，但不是新增的公共节点类型。真实关系方向不随版面列顺序改变。

平面图谱把这几层从上到下排成树，层名在左侧；节点多的层按网格换行，每行个数按面板宽高比选择，使整棵树在面板里尽量大。平面图谱始终显示全景，解题推进时不移动、不缩放，只由学生手动缩放或拖动，“全景”按钮复原。镜头跟随当前步骤的效果只在 3D 视图中使用。

复用 `PracticeMath`、现有交互组件、样式及所需的图像组件；核对组件参数和模板初始化要求。不加载正式 `runtime.js`，避免初始化导师、记录器和学习模式。详情链接使用 `/knowledge/`。

状态推导、SVG 展示和作答者适配分开实现。学生提交、后退和回放共用同一推导函数；提示与动画由状态驱动。支持键盘、减少动态效果、手机长公式；节点状态有文字标识，不只依赖颜色。

LLM 每次只收到：

1. 原题数学表达，以及当前路线已通过步骤的结果。
2. 当前决策问题、真实候选及其条件文字。
3. 本次回答格式。

首次作答前不提供人工结论、判定反馈、未来结果、既有题型匹配标签或预期答案；提交后重试可获得与学生相同的反馈。回答沿用交互值，可附理由和原表达／步骤结果的来源位置；不要求引用新造的事实 ID，也不以“引用与标准答案重合率”评价推理。

学生与 LLM 共用判定和反馈。选择另一条有效但尚未实现的路线时标记“未覆盖”，不计为数学错答。首批自动回放以两条已贯通路线为验收范围：录制不指定路线，D3 的方法由 LLM 自己选，走完后再换另一条路线重走方法步骤，同一份回放连续展示两种方法以便对照。

LLM 录制保留请求、回答、判定与重试；公开回放只导出必要内容。完成两条路线不代表已实现任意题目的自动规划。确定性的表达计算可逐步接入，不确定的候选仍交由 LLM 试算、解释和验证，不预先要求全部判断变为计算谓词。

## 9. 实施顺序与验收

| 阶段 | 工作 | 验收 |
| --- | --- | --- |
| P0 输入与图谱对齐 | 补录 Q01 的既有格式数学表达，完成第 6 节原稿对齐 | 表达与图谱校验通过；题设与求解结果分开 |
| P1 构建 | 决策原稿、候选查询、模板快照、bundle 与 `--check` | 引用有效，产物可重复，版本覆盖完整输入 |
| P2 学生 Demo | 两条路线、图谱同步、后退与换方法 | 正误判定正确，实际调用及依据准确，桌面与手机可用 |
| P3 LLM 与回放 | 同一决策投影、录制、回放 | 两条路线各录制验证；同一作答序列得到相同图谱状态 |

重点测试：

- 原表达是唯一题设来源，未通过步骤的结果不会提前出现；换路线不带入上一条路线的答案。
- $x\in\mathbb R$ 不会导致区间最值法被判错；配方法与顶点法的适用性不因 Demo 实现范围而改变。
- 反向查询不反转语义箭头；辅助线不冒充图谱关系；候选关联不冒充实际执行。
- 配方方法、配方技能按真实类型区分；子方法内部未执行的调用和依据不会进入知识汇总。
- 同一技能重复调用、跳过某次调用、后退及路线叠加均保留正确的发生位置。
- 表达、图谱或模板改变后旧 bundle 可被检出；回放不会混用不同版本。
- 1280×960 与 390×844 下完成两条路线，检查键盘操作、长公式、动画与组件初始化；没有学习记录或导师请求。

本阶段不安排打包、镜像和数据库演练。后续推广到其他题时，再根据真实分支需求扩展；不预设只添加配置就一定能覆盖退化、存在量词和更换主元等新情况。
