# 交互步骤卡片设计规范

适用于阶段三引擎驱动的解题步骤卡片（拍题页 `site/lab/search/problem.html` 的流式路线）。新增或修改步骤模板、交互规则、前端卡片渲染时，都按本规范执行。技术实现见 [阶段三步骤交互卡技术方案](stage-three-step-interaction-design.md)；版式参照 `/2/` 恒成立题库（如 q04、q06）。

## 1. 卡片的两种状态

每个步骤是一张卡片，有两种状态。

| 状态 | 内容 |
|---|---|
| 进行中 | 步骤标题、题干、题干下的题板或题图、作答组件、反馈、确认按钮 |
| 已完成 | 结论层 + 数学推导 |

一个交互有多个小问时，仍是一个步骤、一张卡片：进行中列出全部小问及状态，已答的小问折叠为作答摘要行；完成后只保留一张完成卡，不附各小问的作答记录。

## 2. 已完成卡片：结论层 + 数学推导

已完成卡片固定由两部分组成，自上而下：

1. **结论层**：这一步得到了什么，一眼可读。
2. **数学推导**：标题为「完整推导」，默认展开。

结论层只选一种形式，不重复表达同一结论：

| 形式 | 适用 | 数据 |
|---|---|---|
| 结论板 | 一般步骤：一组带标签的公式，可用连接符（→、⇔） | 模板 `highlight`：`caption`、`items[{label, math, note?}]`、`connector?`、`result?` |
| 合并格子 | 分情况求解后取并集 | `highlight.layout = "merge"`：每种情况一格（情况名 + 本情况结果，空集写「无解」），下面一行「取并集：…」 |
| 分情况图 | 分类讨论最值：每种情况一张图，图就是结论 | 交互小问的 `completion_graphs`；对应数学卡用 `derivation: true`，不带结论板 |
| 单张完成图 | 边界检验、值域等需要看图确认的步骤 | 交互小问的 `completion_graph`，与结论板可同时出现 |
| 仅结论 | 路线最后的结论步骤（如确定最小值） | `highlight.conclusion_only = true`，不显示推导 |

规则：

- 有分情况图时，不再加文字结论板；图下面只放图题（例如「情况①：\(a\le-1\)，最小值在右端点 \(x=\frac12\) 处取到」），不额外生成总结句。
- 结论板里的式子不带区间下标（区间写在标签里），完整推导里保留下标。
- `highlight.result` 是这一步的一行结论，会出现在下一步的「接第 n 步」里；没有时显示学生的作答。

## 3. 数学推导的写法

- 写数学推导，不复述方法。用 ∵/∴ 链，参照 q06。
- 一句一行；模板里的 `\n` 另起一行。
- 分情况的结论按 ①②③ 编号，每种情况一行，例如「① 当 \(-\frac a2\ge\frac12\)，即 \(a\le-1\) 时，\(g(x)_{\min}=g(\frac12)=\frac a2+\frac54\)；」。
- 求参数范围用方程组写法：「① 由 \(\begin{cases}a\le-1,\\ \frac a2+\frac54\ge0\end{cases}\) 得 \(-\frac52\le a\le-1\)；」，空集写「得 \(a\in\varnothing\)」，最后一句「综上，取并集得 …。」
- 最值取不到时写成不等式加说明，例如「\(g(x)>g(0)=1\)，最小值取不到」。
- 函数有名字时用名字（`g(x)`、`h(x)`），名字由方法输入绑定，模板里不写死。

## 4. 进行中卡片

### 4.1 题干

- 用一句话问清楚要做什么，口径与 q04 一致。例如「三种情况下，都要求区间上的最小值不小于 \(0\)。\(a\) 的取值范围是什么？」。
- 题干里已经写出的式子，题板和上下文里不再重复。

### 4.2 题干下的内容（只选一种）

| 形式 | 适用 | 数据 |
|---|---|---|
| 题板 | 需要把前面各情况的结果列出来再作答 | 规则 `board: {caption, lines}`，交互输出 `stem_board`；例如「各情况各自要满足」，每行「① \(a\le-1\)：\(g(x)_{\min}=\dots\ge0\)」 |
| 题图 | 需要看图或拖动观察 | 规则 `graphs.stem`，例如可拖动对称轴的 `axis_explorer` |
| 上下文 | 默认 | 本步数学卡的 `before` 公式（第一问才显示） |

### 4.3 选项

- 选项是数学结论本身，写法与推导一致。参数范围用不等式写法（\(a\ge-\frac52\)），空集写「无解」，全体实数写 \(a\in\mathbb R\)。
- 干扰项来自真实的常见错误（漏掉一种情况、端点开闭、没和本情况取交集等），选中后给出针对性反馈。
- 选项图（数轴等）只在图能帮助区分时使用；文字已经清楚时不加。

## 5. 分类讨论步骤的组织

以区间最值法为例，参照 q04：

1. **分类讨论最值**：先选分类依据，再在清单里判断各情况最值的位置（可拖动对称轴辅助）。完成卡 = 分情况图 + 完整推导。
2. **求参数范围**：题板列出各情况要满足的条件，选最终范围。完成卡 = 合并格子 + 完整推导。

每种情况单独的求最值、求范围卡片不再作为独立步骤出题（交互规则 `fold: true`）。它们仍保留在数学记录里供知识图谱点亮，随下一步显示在折叠区「各情况的推导」中。

## 6. 图像

- 图像规格全部由服务端从精确值生成，前端不做数学计算。
- 一组图要么全部画出，要么都不画：任何一张无法如实画出或数据不合法，就整组降级为文字，题目与答案不受影响。
- 分情况图共用同一个坐标窗口，便于对比；每张图的对称轴只能在本情况范围内拖动，开区间端点拖不到。
- 空心点表示取不到，实心点表示取到；目标点标「最低」「最高」，取不到的开端标「下端」「上端」。

## 7. 命名与标题

- 步骤标题与 `/2/` 题库保持一致，例如「分类讨论最值」「求参数范围」「检查边界」「确定最小值」。
- 情况编号用 ①②③，在题干、题板、图题、结论层和推导里保持同一编号。
