## 1. 核心判断

1. **三层页面建立在同一套数据上。** 专题页按专题展示，知识图谱页展示全部，个人图谱在上面叠加本人的练习情况。先建数据，再做页面；页面不各自维护知识点列表。
2. **数据拆成三类文件，各管一件事。** 图谱只有点和边；专题与图谱的关联由每个专题各自的文件维护；节点怎样展示单独一个文件（第 3 节）。
3. **方法和知识点都是图谱节点，类型不同。** 知识点是可以单独学会、跨题复用的一条规律；方法用到若干知识点，选对方法、走完路线本身也是一项能力。“表达式的变形方法”归为方法的子类，不设第三种顶层类型。公共图谱只连接直接学习前提与方法的核心知识依据；必要连线以节点清单第 5 节为准。方法之间不连线；不同方法如何组合、按什么顺序使用，由具体题目的路线表达。
4. **步骤是知识点的使用记录。** 专题文件逐题写明每一步用到哪些节点；“这个知识点在几道题里练过”“这道题需要哪些知识点”都由它汇总得出。
5. **个人图谱只展示有证据的结论。** 现有数据只有“练习过”和学生自评，只能叫“练习覆盖”和“自评”，不能叫掌握度。刷题入库后（第 7.7 节）每个节点有服务端判分的刷题结果，叫“刷题状态”（第 9.2 节）；整题里的步骤级证据是否记录仍要单独决定（第 10 节）。
6. **节点全局唯一，专题只是投影。** 同一知识点或方法只建一个节点，专题选择全局节点 ID 的子集；不同专题可选到同一节点。当前清单去重后有 14 个知识节点，节点定义与重复项归属见清单第 4 节。节点和边由人编写、测试校验，不用 LLM 自动生成边。
7. **图解跟着节点走，不跟着页面走。** 每个知识点、每个方法的图解是一个独立模块，文件名就是节点 ID；任何页面按 ID 打开同一份图解。专题相关的部分（示范题、本题说明）由调用方传入，图解本身不感知专题（第 6 节）。
8. **知识点靠刷题练，方法按整题练。** 练一个知识点时做作者为它写的小题，每题自带已知条件，只考这一步的判断；选方法、串联步骤的能力仍由整题练习负责（第 7 节）。
9. **专题组织题目，详情页讲知识点。** 专题页按题型排题，整题练习从这里进入；每个知识点、方法有一个详情页，讲清它是什么并提供刷题（第 8 节）。题号只在专题页内有意义：知识地图、知识图谱、图解底部、详情页都不列题目。

## 3. 数据：三类文件

### 3.1 分工

三类文件各回答一个问题，各自独立修改：

| 文件 | 回答的问题 | 维护方式 |
| --- | --- | --- |
| `site/data/knowledge/graph.json` | 有哪些知识点和方法，它们之间是什么关系 | 全站一份，只有点和边 |
| `site/data/knowledge/topics/<专题 ID>.json` | 这个专题用到哪些节点，每道题的每一步用到哪些，方法的步骤顺序 | 每个专题一份，由该专题的作者维护 |
| `site/data/knowledge/display.json` | 每个节点怎样展示：一句话说明、有没有知识点弹层 | 全站一份 |
题页不感知图谱。题页配置里只保留现有的 `tip`：它带有本题的“本题”说明，属于题目内容。新增专题时加一个专题文件；用到图谱里还没有的节点，在 `graph.json` 补节点和边、在 `display.json` 补展示；再在图谱页配置里加上这个专题文件。其他专题的文件不用动。

### 3.2 `graph.json`：点和边

保留两种顶层类型，“表达式的变形方法”作为方法子类；通过改写条件或目标进行求解，并同步处理定义域、变量范围与等价条件。以下子类字段与两类连线为数据约定；现有数据、页面和测试需按此约定迁移。

```json
{
  "nodes": [
    {"id": "extremum-transfer", "kind": "knowledge", "label": "恒成立、存在成立与函数值域的关系"},
    {"id": "quadratic-interval-extremum", "kind": "knowledge", "label": "二次函数在区间上的最值与值域"},
    {"id": "quadratic-function-properties", "kind": "knowledge", "label": "二次函数的图像与性质"},
    {"id": "quadratic-inequality-solve", "kind": "knowledge", "label": "一元二次不等式的解法"},
    {"id": "method-discriminant", "kind": "method", "label": "判别式法"},
    {"id": "method-interval-extremum", "kind": "method", "label": "区间最值法"}
  ],
  "edges": [
    {"type": "uses", "from": "method-discriminant", "to": "quadratic-function-properties"},
    {"type": "prerequisite", "from": "quadratic-function-properties", "to": "quadratic-inequality-solve"}
  ]
}
```

- 节点必填 `id`、`kind`、`label`；方法节点可选 `subtype`，表达式的变形方法取 `technique`，知识点不填。未标子类的方法可省略该字段。`id` 小写短横线，全站唯一，发布后不改名、不复用；以后有步骤证据引用它时，改名需要迁移。方法以 `method-` 开头。`kind` 为 `knowledge`（知识点）或 `method`（方法）。
- 边只有 `type`、`from`、`to`，仅两种类型：
  - `uses`：只能从方法指向知识点，只表示方法成立的核心知识依据，不包含个别题目的后续运算，不带顺序；例如“配方 → 平方的非负性”。
  - `prerequisite`：只能连接两个知识点，表示当前课程中的直接学习前提；证明中用到不等于必要依赖，只保留覆盖边（不写可由传递推出的边）。
- 方法之间不连线；允许节点没有连线。具体路线用到的知识与先后顺序记录在专题文件中，不自动转为全局边。
- 同义名称、跨专题名称和文档内的 B/Q 编号不生成额外节点。合并映射以清单第 4 节为准；已有数据迁移时，旧 ID 的引用与学习证据统一归入唯一 ID，不能保留为平行节点。
- 不写专题归属、展示文字或顺序。节点可以暂时没有任何专题练到（例如某个前提知识），图谱页显示为“本站暂无练习”。

### 3.3 专题文件：专题与图谱的关联

以 `topics/quadratic-always.json` 为例：

```json
{
  "id": "quadratic-always",
  "label": "一元二次不等式恒成立问题",
  "path": "/2/",
  "nodes": ["method-interval-extremum", "extremum-transfer", "quadratic-function-properties", "quadratic-interval-extremum", "case-merge", "endpoint-attainability"],
  "methods": [
    {
      "node": "method-interval-extremum",
      "route": "interval",
      "group": "group-interval",
      "sequence": ["extremum-transfer", "quadratic-interval-extremum", "case-merge", "endpoint-attainability"]
    }
  ],
  "problems": {
    "quadratic-always-q04": {
      "label": "Q04",
      "path": "/2/q04/",
      "routes": {
        "interval": {
          "i_basis": ["method-interval-extremum"],
          "i_condition": ["extremum-transfer"],
          "i_extremum": ["quadratic-interval-extremum"],
          "i_range": ["case-merge"],
          "i_boundary": ["endpoint-attainability"]
        }
      }
    }
  }
}
```

- `nodes`：本专题展示范围，只保存全局节点 ID，不复制名称、定义或关系。专题图展示这些节点及两端都在范围内的全局边；需要补充前置知识时加入已有 ID。示例中的 `quadratic-function-properties` 是展示所需的前置节点，不因出现在这里就计为本题练习记录。
- `methods`：本专题的方法、它在题页配置里的路线 ID（`route`，`/2/` 的分离参数法是 `extremum`）、目录页分组（`group`），以及本专题里这条路线的步骤顺序（`sequence`）。顺序是专题的编排，同一个方法换个专题可以不同，所以不放进图谱。`sequence` 列出这条路线在各题中用到的全部节点（方法本身除外），只在个别题出现的也列入，知识地图按它排卡片。可选 `examples`：方法图解底部的示范题，`[{"problem": "quadratic-always-q01", "note": "开口向上且判别式小于 0"}]`，题目须在本专题且有这条路线；示范题的说明属于专题内容，所以写在这里而不写进图解（第 6.4 节）。
- 题号 `label` 只在专题页内使用；详情页不列题目，专题文件不另写题干。
- `problems`：逐题、逐路线、逐步骤写出用到的节点。逐题写明而不按步骤 ID 套默认规则，读的人和程序都不用推断（Q01 与 Q04 的 `e_extremum` 对应的节点就不同）。
- 每个步骤都要出现；纯誊写、不练任何规律的步骤（如 `d_rewrite` 整理不等式）写空数组，表示作者确认过。
- 每条路线的第一步“判断适用条件”（`_basis`）对应该方法节点本身：选对方法、核对前提，是方法这项能力的证据。
- 同一个 ID 被两个以上专题的 `nodes` 选中，就是跨专题展示节点；是否在多个专题被练到，另按 `problems` 统计。展示前置知识不增加练习次数。
- 全局名称、定义与依赖共用；本题案例、内容侧重和路线顺序由专题与题目配置提供，不覆盖全局定义。
- 专题页、图谱页直接读专题文件统计“出现在几道题、几个步骤”，不需要另生成索引。详情页是生成的静态页面，内容在生成时写入（第 8.5 节）。

### 3.4 `display.json`：节点的展示

```json
{
  "extremum-transfer": {"summary": "恒成立看最不利的点，存在看最有利的点。", "sheet": "extremum-transfer"},
  "method-interval-extremum": {"summary": "x 只在某个区间上取值时，直接讨论函数在区间上的最值。"}
}
```

- `summary`：一句话说明，用于知识地图小卡、图谱详情面板。两个容易混淆的节点，各自的 `summary` 写清区别。
- `sheet`：节点有图解时填写，值等于节点 `id`，表示 `site/assets/explain/<knowledge|method>/<节点 ID>.js` 存在（第 6 节），知识点和方法同样适用；没有图解的节点不写。目前图谱的 27 个节点都有图解。
- 以后节点有其他展示形式（图标、示意图组件）也加在这里，不进图谱和专题文件。
- 方法图解的讲解部分全局共用；各专题不同的示范题写在专题文件的 `methods[].examples` 里。

### 3.5 节点映射与复用

节点定义、重复项与必要连线统一维护在[知识点与方法清单](knowledge-graph-topic-inventory.md)。`/1/` 引用 B1–B7、M1–M9；`/2/` 引用对应知识与四个通用方法，逐题可补充其他已有节点。

“一正、二定、三相等”共用 `amgm-formula`，步骤说明具体条目。配方操作引用 `method-complete-square`，配方后的函数性质引用 `quadratic-function-properties`。不把步骤名或学习空间技能原子直接转换为图谱节点。

同一节点跨专题只计一个节点；全局练习题数按题目 ID 去重，步骤覆盖另计，练到一个内部条目不等于掌握整个节点。方法节点除了步骤标注，还要算上走它自己路线的题：`/1/` 直接法的步骤只标 `amgm-formula`，不标 `method-amgm-direct`，只看步骤会把它算成“暂无练习”（`site/knowledge/data.js` 按专题文件的 `methods.route` 合并，按题去重）。

## 4. 第一层：专题页的知识地图

位置：`/1/`、`/2/` 目录页，在方法分组之后新增一节“本专题的知识点和方法”。

- **布局：** 每个方法一列（窄屏改为每个方法一行，可展开），列内按专题文件中的 `sequence` 排出知识点小卡，卡片之间用细箭头表示先后。同一个知识点出现在多个方法里时，每列都显示，悬停或点选时所有出现处一起高亮，学生能看到“这个知识点四个方法里有三个都要用”。
- **知识点小卡：** 名称、“出现在 N 道题、M 个步骤”。小卡不标“也在其他专题”，跨专题的信息只放在详情面板里。
- **点开：** 在地图下方显示详情面板：`summary`、本专题里用到它的方法、前提与后续；有 `sheet` 的加“看图解”；最后是“查看详情 →”，链接到该节点的详情页（第 8 节）。面板里不列题号。
- **方法列标题：** 方法名与知识点小卡一样，点开显示详情面板（面板里有“查看详情”）；“图解”打开该方法节点的图解（第 6 节）。
- **入口：** 步骤知识点弹层原先决定不在目录页放入口；有了知识地图，目录页的入口就是这一节。
- 详情页讲知识点并提供刷题（第 8 节），不列题目；题目仍在目录页的方法分组里。

数据来自 `graph.json`、本专题文件和 `display.json`；详情面板的“也在其他专题”需要同时读取其他专题文件。页面加载后由一个共享脚本渲染，不需要服务端改动。

## 6. 知识点与方法的图解：独立模块

### 6.1 目标

- 一个节点一份图解，任何页面（练习页、专题目录页、知识地图、知识图谱页）按节点 ID 打开同一份。
- 新增或修改一个图解只动它自己的文件和 `display.json` 的一行，不改弹层外壳，也不改调用它的页面。
- 不点不加载；一份图解出错只影响它自己。

### 6.2 文件结构

```text
site/assets/explain/
  explain.js          # 外壳：openExplainer(id, options) 弹层；renderExplainer(root, id) 详情页内展示
  explain.css         # 弹层样式，以及方法图解共用的版式（核心、判断、图、三步）
  shared/             # 图解共用的工具（目前只有 html.js 的转义）；画图工具等第二份图解用到时再提出来
  knowledge/<节点 ID>.js（可带同名 .css）
  method/<节点 ID>.js
```

原来的单独查看页 `/knowledge/explain/` 已删除（未发布过）：详情页直接在页面里展示图解（第 8.3 节），不再需要一个只为打开图解的页面。

每份图解是一个 ES module，不是“每个节点一对 HTML+JS”：图解要和宿主页共用样式、KaTeX 和弹层；独立 HTML 要么用 iframe 嵌入（样式隔离、高度和手机键盘难处理，宿主变量传不进去），要么取回来再拼进页面（相当于自己写模板加载器）。模块用宿主页已有的环境，测试也能直接检查文件。

### 6.3 模块约定

```js
export default {
  render(context) { return `<p>…$a+b\\ge 2\\sqrt{ab}$…</p>`; },  // 必需：返回 HTML，可含公式
  mount(root, context) { /* 可选：交互图等 */ return () => {}; },  // 可返回清理函数
  stylesheet: new URL('<节点 ID>.css?v=1', import.meta.url).href,   // 可选：只属于这份图解的样式
};
```

- 标题、种类不写在模块里，由外壳从 `graph.json` 取，避免两处名称不一致。`extremum-transfer` 原来的标题“恒成立、存在，怎么转化为最值”因此改为节点名称。
- `context` 由外壳传入：`{node, tip, topic}`。`tip` 即练习页现有的 `{case, note}`，本步完成后才传，用于标出总结表中本题那一格；`topic` 是专题文件内容（节点不在该专题时为空）。
- 每次打开都重新 `render` 和 `mount`，图解不需要自己处理“再次打开”的状态。
- 图解不发请求、不读取页面全局变量、不修改弹层以外的元素；样式只依赖宿主页的 `--ink`、`--muted`、`--teal`、`--teal-dark`、`--line`、`--paper` 变量（其余几个由 `explain.css` 在弹层上自带），独立样式表里的选择器都以 `.explain-<节点 ID>` 开头。
- 跳到另一份图解写成 `<button data-explain-open="节点 ID"></button>`，按钮文字留空时外壳填节点名称。
- 外壳负责：建一个 `<dialog>`（手机上从底部弹出）、动态 `import` 模块、插入样式（每份只插一次）、渲染公式、调用 `mount`、关闭或切换时调用清理函数。页面没有 KaTeX 时（如专题目录页），遇到含公式的图解再加载。模块或 `graph.json` 加载失败时 `openExplainer` 返回失败，由调用方提示，不影响页面。

### 6.4 弹层底部

图解正文全局共用，弹层底部只有一行“查看“分离参数法”的详情 →”，链接到 `/knowledge/<节点 ID>/`；刷题在详情页（第 7、8 节）。

- 练习页打开时传 `detail: false`，不加底部，避免把学生从正在做的题引走。
- 知识地图传当前专题；知识图谱页传当前筛选的专题，没有筛选时节点只属于一个专题就用这个专题。`topic` 只给方法图解读本专题的方法与示范题，不进链接。
- 详情页内嵌的图解（`renderExplainer`）没有底部；图解里跳到另一份图解的按钮在详情页上改为跳到那个节点的详情页。

最初的方案是由外壳在底部追加示范题、练到它的题、专练入口和“在知识图谱中查看”；详情页实现后都已去掉，`graphLink` 选项随之取消。

   - `square-nonnegative`（平方的非负性）：四个 $a\times b$ 长方形拼成边长 $a+b$ 的正方形，中间空出 $(a-b)^2$，拖动 $a$ 看空洞缩成一点；附常用写法表。说明：与基本不等式的区别、平方项为 $0$ 取等、和积的范围 $s^2\ge4p$。
   - `homogeneous-expression`（齐次式）：各项次数的标签、$\left(\frac5x+\frac4y\right)(x+5y)$ 的乘法表（每格都是零次），再用 $(x,y)=(2k,k)$ 拖动 $k$，看一次式、负一次式、零次式怎样变。说明：只给缺的那部分乘、乘入的式子要等于 $1$、零次式化成比值。
   - `symmetric-polynomial`（对称多项式用和与积表示）：六个式子，选一个看交换 $x$、$y$ 前后是否相同，对称的给出 $s$、$p$ 写法，不对称的给出 $a=x$、$b=2y$ 的构造；`tip.case` 为 `construct` 时直接打开构造的例子。附常用改写表。
   - `method-reciprocal`（取倒数）：$y=\frac{2x}{x^2+4}$ 与 $\frac1y$ 两条联动数轴，拖动 $x$ 看两点反向移动、$y$ 最大时 $\frac1y$ 最小；方法三步与三条说明（什么时候想到取倒数、$y$ 能等于 $0$ 先单独看、有正有负不能直接取倒数）。
   - `/1/` 题页 30 题共 149 步配了 `tip`，`note` 写本题这一步的具体式子和取值。被 `tip` 指向的 4 个方法图解（配凑、配齐次式、换元、分式分离）补上了“本题”说明，样式 `.method-problem` 在 `explain.css`。契约测试新增：`tip` 只含 `id`、`case`、`note`，`case` 必须是该图解认得的值，被指向的图解必须渲染 `problemNote(tip.note)`。
   - 人工审阅后：`method-homogeneous` 加“整体乘入／只乘一部分”两页，后一页用 $x+y=1$、$\frac1x+\frac xy$ 逐项数次数，并对比整体乘会把零次项乘成一次；Q01、Q09、Q30 的提示改为跟随选择分支（第 4 节）。

方法图解正文里的“读题信号 · 第 02 题”等仍引用 `/2/` 的题号；这些方法目前只在 `/2/` 使用，等有第二个专题用到同一方法时，再把这些例子改成不依赖题号的写法。

## 7. 刷题

### 7.1 定位

知识点是在某一步里用到的，练知识点只需练这一步的判断，不必整题重做；同一个知识点连续做几道情形不同的小题，更容易看出它的共同形式。整题练习不被取代：选哪种方法、怎样把步骤串起来，只有整题才练得到，整题练习从专题页进入。

学生来详情页（第 8 节）一是看懂知识点，二是刷题，所以刷题按钮放在图解的标题行上：点“刷题 · 8 题”，在弹层里一题接一题地做，不离开页面。

### 7.2 小题怎么写

- 每个节点一个文件 `site/data/knowledge/drills/<节点 ID>.json`，由作者手写，不从题页截取。每题自带需要的已知条件，学生不需要读原题和前面的推导。
- 按图解里的情形出题（恒成立或存在、大于或小于、端点能否取到、参数在哪一边、带负号），不按原题一一对应：原题里重复的情形只留一题，原题没覆盖的情形补上。每个节点 10 题左右，至少是每次抽题数的两倍（第 7.7 节）；多选题适合检查“几种说法是否意思相同”。
- 字段：

```json
{
  "node": "extremum-transfer",
  "items": [{
    "id": "exists-gt-open",
    "given": "已知 …（可选，一两行）",
    "question": "要使存在 $x\\in(1,2)$，使 $f(x)>0$，$f(x)$ 应满足哪个条件？",
    "type": "choice",
    "options": [
      {"value": "min", "label": "$x\\in(1,2)$ 时，$f(x)$ 取值范围的下端 $>0$", "feedback": "下端也大于 $0$ 是所有点都满足……"},
      {"value": "max", "label": "$x\\in(1,2)$ 时，$f(x)$ 取值范围的上端 $>0$"}
    ],
    "answer": "max",
    "source": "quadratic-always-q05/interval/i_condition"
  }]
}
```

- `type` 只有 `choice`（单选，`answer` 是一个值）和 `multi`（多选，`answer` 是值的数组）。每个错误选项都要写 `feedback`，正确选项不需要。正确答案的位置由作者错开，不随机打乱，便于检查。
- 抽象函数 $f(x)$ 在闭区间上不一定有最值；选项里写 $f(x)_{\max}$、$f(x)_{\min}$ 时，`given` 要写明“图像是一段连续曲线，有最大值和最小值”（测试检查），否则改用“取值范围的上端、下端”或具体函数。反例题要真的成立：作者写“不能只看两端”这类题时，先找一个只看两端会判错的具体取值，写进反馈。
- `source` 可选，写这道题由哪道题的哪一步改写而来，只用于追溯，页面不显示；测试检查专题文件里该步骤确实对应本节点。
- 公式写 `$…$`，与题页相同。生成脚本校验以上约定，不合格时报错。

### 7.3 弹层的行为

- 一次一题：顶部进度条和“第 3 / 8 题”，多选题标“多选”；有 `given` 时先显示已知。
- 选好后提交。答错：所选的错误选项标红并显示它的 `feedback`（多选只是漏选时提示“还有正确的选项没选上”），改选后再提交。答对直接进入下一题，最后一题答对后直接显示小结；道理放在错误选项的 `feedback` 里，答对时不另外讲。
- 小结：一次答对几题、每题“一次答对”或“改了 N 次”，以及“再刷一遍”“回到图解”。
- 中途关掉再打开，从停下的那题继续；做完后再打开从头开始。
- 现在在浏览器里判分，不发请求、不保存结果（答案写在页面里，与题页一样）；入库后改为服务端抽题判分，见第 7.7 节。按钮在脚本加载前隐藏；脚本加载失败时按钮提示刷新，页面其余部分照常可用。
- 代码：弹层是 `site/knowledge/drill.js`，点按钮时才加载；样式在 `node.css`。小题由生成脚本嵌入页面的 `<script type="application/json" id="kn-drill-data">`（去掉 `source`）。

### 7.4 试点与后续

- 先写了 `extremum-transfer`（8 题：四种情形各一，参数在左边、带负号、端点取不到各一，外加一道多选）。
- `/2/` 的 4 个方法各 5 题，练“看题判断能不能用这种方法”，说法与图解的前提清单一致：
  - `method-discriminant`：系数确定非零可直接用、系数含参数先讨论为 0、只在区间上判别式不够、带等号用 $\Delta\le0$、开口方向也要列。
  - `method-interval-extremum`：闭区间可用、全体实数时判别式更直接、无穷区间也算区间、开口方向不是前提、有解问题同样适用。
  - `method-separation`：除以正数、除以负数变向、除数符号不定不能直接除、已经分离、参数分不开的式子。
  - `method-variable-swap`：主元选给出范围的字母、固定另一字母后是一次形式、一次形式只看两端、恒成立针对的就是自变量时不用换、关于主元是二次式时不能只看两端。
- 入库前先把这 5 个节点各补到 10 题左右，每次随机抽 5 题才不会总是同一组（第 7.7 节）。
- 随图解分批写的知识点（第 6.6 节），每个 8 题：
  - `endpoint-attainability`：恒成立和存在、带不带等号、取得到和取不到的六种组合各一题（数值都是新写的），退化情形留下的边界一题，再加一道多选（“带等号就一定保留”“不带等号就一定排除”都是错的）。
  - `case-merge`：“且”取交集、某种情况与前提交集为空、交集的端点、并集的端点、某种情况全部满足时整个前提并进来、退化情形也要并进来、开口方向和 $\Delta$ 取交集，再加一道多选（哪些地方取并集）。
  - `quadratic-function-properties`：开口向上且 $\Delta<0$、恒 $\le0$ 的条件（不能漏 $\Delta=0$）、系数 $m^2+1$ 不用分类、系数为 $0$ 的退化情形、配方求顶点、$\Delta=0$ 的含义、对称轴在区间外的最小值，再加一道多选（哪些条件保证恒正，含 $a=b=0$、$c>0$）。
  - `quadratic-interval-extremum`：对称轴在区间右侧求最小值、和中点比求最大值、由最小值在哪个端点反推对称轴位置、由最大值在哪个端点反推（和中点比就够）、开区间的取值范围、开口向下、半无限区间，再加一道多选。
  - `quadratic-inequality-solve`：两根之间、两根之外带等号、开口向下先乘 $-1$、完全平方式的 $>0$ 与 $\le0$、$\Delta<0$ 的 $<0$ 无解、解关于参数的不等式，再加一道多选。
  - `reciprocal-sum-function`：求最小值、最低点位置、区间在最低点一侧、两端比较（两端点之积与 $k$）、开区间取值范围、$x<0$ 的最大值、先提负号，再加一道多选。
  - `inequality-properties`：乘负数变向、除以负的 $x$、$x$ 符号不定不能直接除、同正取倒数、异号取倒数、同向相加、相减要先变成加相反数，再加一道多选。
  - `linear-interval-extremum`：递增、递减、斜率为 $0$、恒正只看两端、斜率恒正、开区间的端点条件、两端异号，再加一道多选。
  - `function-monotonicity`：定义、单调函数的取值范围、和的单调性、取倒数、乘负数、复合（第 07 题的同类）、单调区间不能写成定义域，再加一道多选（开区间取不到端点值）。
  - `method-complete-square`：基本配方、求最小值、二次项系数为 $-1$、为 $2$、取等条件、范围受限时取不到、配方说明恒正，再加一道多选。
  - `amgm-formula`：直接求最小值、$x<0$ 不满足一正、凑系数求最大值、取等取不到（$\sqrt{x^2+4}+\frac1{\sqrt{x^2+4}}$）、定和求积、凑项、两次使用取等不能同时成立，再加一道多选。
  - `square-nonnegative`：配成两个平方和、取等条件、哪个不一定成立（$a+b\ge2\sqrt{ab}$）、和积的范围、$a^2+b^2=2$ 时 $ab$ 的两侧范围、$x^2+\frac1{x^2}$ 的最小值、$(a+b)^2\ge4ab$，再加一道多选。
  - `homogeneous-expression`：求次数、识别零次式、乘什么配成零次、条件不等于 $1$ 时的系数、零次式只和比值有关、计算最小值、令 $t=\frac xy$，再加一道多选。
  - `symmetric-polynomial`：识别对称式、$x^2+y^2$、$x^3+y^3$、$\frac1x+\frac1y$ 用 $s$、$p$ 表示、实数存在的条件、$x+y$ 的范围、不对称时怎样换元，再加一道多选。
  - `/1/` 的 8 个方法各 5 题：直接法（何时能用、定积、定和、系数、指数）、配凑（加减常数、凑系数、凑分式、负数时的最大值）、配齐次式（两次使用的陷阱、条件不等于 $1$、拆项补齐、反过来乘）、消参（解出变量、凑项、消元后的范围、何时消元）、换元（改写、求值、新变量范围、何时换元）、分式分离（逐项拆开、换元后再拆、何时分离）、取倒数（换回、先判符号、转化目标、值域、异号要分段）、和积换元（$s$、$p$ 改写、范围、为什么要 $s^2\ge4p$、正数条件）。
- 恒成立专题的 15 个节点、`/1/` 专题的 12 个节点都已有小题，图谱 27 个节点全部覆盖。
- 题页里这些步骤多数是单选和多选，填空只有少数，所以小题暂不支持填空。
- 以后可由求解器生成参数化的变式题，答案和反馈由程序校验（只定方向）。

### 7.5 已删除的第一版

最初做的是“题页自动走到某一步”：题页地址带 `?drill=` 时，按标准答案自动完成前面的步骤，只留目标步骤，详情页按（题目、步骤）逐行列出原题和“练这一步”。实际用下来，学生每次都要先读一整道原题、被带离详情页，同一种判断在几道题里重复出现，详情页也成了一长串题目清单。改为手写小题后，这套代码（`site/assets/practice/drill.js`、`runtime.js` 的专练分支、`context.js` 的 `answerActions` 及对应测试）在发布前删除，题页恢复为只有整题练习。原计划的“精简已知”（在题页步骤上写 `given`）也由小题自带的 `given` 取代，题页配置不加这个字段。

### 7.6 与证据的关系

刷题结果入库后单独成表（第 7.7 节），由它推导节点的刷题状态（第 9.2 节）。整题的步骤级证据如果以后记录，与刷题的区别记在 `mode` 字段（第 9.3 节）：`whole` 整题、`drill` 刷题。刷题不改变题目的“练习过”标记和自评：那两项说的是整题。

### 7.7 入库、抽题与计入个人图谱（已定方案，待实施）

第 7.3 节是现在的做法：小题连同答案写在页面里，浏览器判分，不保存。要让刷题结果更新学生自己的知识图谱，判分必须在服务端，答案和反馈都不能下发到页面（只有正确选项没有反馈，下发反馈等于下发答案）；否则看页面源码就能“刷题通过”。

**题库**

- 原稿仍是 git 里的 `site/data/knowledge/drills/<节点 ID>.json`，第 7.2 节的格式与校验不变，便于审阅和回滚。部署时由导入工具 `server/tools/import_drills.py` 写入数据库，数据库是运行时题库。
- 导入可重复执行：内容不变不写；内容变了新增一个修订号；文件里删掉的题标为停用，不物理删除，历史记录仍能对上当时的题。
- 表 `knowledge_drill_items`：

| 字段 | 含义 |
| --- | --- |
| `node_id`、`item_id`、`revision` | 主键。`item_id` 发布后不改名、不复用；改了题干、选项、答案或反馈就升修订号 |
| `content` | 下发给学生的部分：`given`、`question`、`type`、选项的 `value` 与 `label` |
| `answer`、`feedback` | 只在服务端使用：答案，以及各错误选项的反馈 |
| `source` | 追溯用，不下发 |
| `content_hash` | 导入时判断内容是否变化 |
| `active` | 是否在抽题范围内；每个 `item_id` 只有最新修订可以是 `active` |

- 每个节点的题量至少是每次抽题数的两倍（每次 5 题就至少 10 题），随机才有意义；不足时每次都是全部题目，只打乱顺序。现有 5 个节点要补到 10 题左右（第 7.4 节）。

**抽题**

- 每次 5 题，题库不足 5 题时取全部。
- 登录学生按以下顺序取，每一档内部随机，取满 5 题后整体打乱顺序：
  1. 最近一次做这道题时没有一次答对的（改过才对，或没做完）；
  2. 没做过的；
  3. 其余的，按最近一次做的时间从早到晚。
- 游客纯随机。
- 选项顺序每次随机打乱，判分按 `value`，与位置无关，学生不能靠记位置答题。第 7.2 节“正确答案位置由作者错开”只约束原稿。

**接口**（`/api/knowledge/drills`，与学习标记共用登录、`X-Learning-User` 和来源校验）

| 接口 | 作用 |
| --- | --- |
| `POST /{node}/sessions` | 开始一轮：抽题，返回会话标识和题目（只有 `content`）。登录时写一条刷题记录；游客不写库，返回签名的会话令牌 |
| `POST /sessions/{session}/answers` | 提交一题 `{position, attempt, value}`：返回是否答对；答错时返回所选错误选项的反馈，或“还有正确的选项没选上” |
| `GET /states` | 本人各节点的刷题状态（第 9.2 节），个人图谱和详情页使用 |

- 游客：服务端照样抽题、判分，但不保存。会话令牌用服务端密钥签名，内含节点、题目与修订号、签发时间，2 小时内有效；提交时验签，不查库也能判分。
- 幂等：`(会话, position, attempt)` 唯一，网络重试同一次提交只记一次；`attempt` 由前端从 1 开始递增。一题答对后锁定，不再接受提交。
- 会话只属于创建它的学生，提交他人的会话返回 404；换了账号返回 409（与学习标记相同）。游客中途登录，这一轮不转入账号。

**记录**

- 表 `knowledge_drill_sessions`：`id`、`user_id`、`node_id`、`started_at`、`completed_at`（全部答对时写入）、`item_count`、`first_try_count`。
- 表 `knowledge_drill_answers`：`session_id`、`position`、`item_id`、`revision`、`wrong_attempts`、`first_try`（第一次提交是否答对）、`completed_at`。只存对错和次数，不存学生选了哪个选项，与第 9.3 节“不保存学生填写的内容”一致；以后要按错误选项分析题目质量时再单独决定。
- 没做完的一轮不计入状态，只用于让没做完的题下次优先抽到。
- 记录保留到账号注销，注销时一并删除；查看明细与按节点清除见第 10 节。

**页面**

- 生成脚本仍校验原稿，但不再把题目写进页面，只写节点 ID；按钮改为“刷题 · 每次 5 题”。`kn-drill-data` 及对应测试随之删除，测试改为检查页面里没有答案。
- 弹层的一题一题、答错反馈、答对直接进入下一题都与第 7.3 节相同，只是取题、判分改为请求接口。请求失败时显示“刷题暂时打不开，请稍后再试”，不退回浏览器判分。
- 小结增加一行：登录时写“已计入你的知识图谱：判别式法 · 刷题通过”，链接到个人图谱；游客写“登录后刷题，结果会计入你的知识图谱”。
- 关掉弹层再打开，在本页内继续这一轮；刷新页面或做完后再打开，开始新的一轮、重新抽题。没做完的那一轮留在记录里，不计入状态。

## 8. 知识点与方法的详情页

### 8.1 定位

每个知识点、每个方法一个页面，只做两件事：讲清它是什么（说明、关系、图解，方法另有步骤图），以及刷题（第 7 节）。详情页不列题目：题目由专题页按题型组织，整题练习从专题页进入。

题目曾经两次出现在这些位置：先是知识地图、知识图谱面板和图解底部直接列题号（Q01、Q04…），后来改到详情页按（题目、步骤）列出原题和“练这一步”。题号离开专题页没有意义（`/1/` 加入后两个专题都有 Q05），列原题又要学生先读一整道题，两种做法都已去掉。

### 8.2 地址与文件

```text
site/knowledge/<节点 ID>/index.html   # 每个图谱节点一个完整的静态页面，由 tools/build-knowledge-pages.mjs 生成
site/knowledge/node.js、node.css       # 详情页脚本与样式（含刷题弹层的样式）
site/knowledge/drill.js                # 刷题弹层
site/assets/explain/links.js           # TOPIC_URL 与 detailHref，图解外壳、知识地图、知识图谱和生成脚本共用
```

- 地址是 `/knowledge/extremum-transfer/`、`/knowledge/method-interval-extremum/`，不带参数，直接可读、可分享。节点 `id` 发布后不改名（第 3.2 节），所以地址稳定。
- 图谱里每个节点都有详情页。没有图解、没有小题、也不是方法的节点，显示说明、关系和“图解和刷题还在整理中。”
- 页面内容在生成时全部写进 HTML：标题、以 `summary` 为描述的 `<meta>`、页头、关系、方法步骤图、小题数据。公式写成 `data-math-text`，由 KaTeX 在浏览器里渲染。
- `node.js` 只做静态 HTML 做不了的事：渲染公式、在页面里展示图解、打开刷题弹层。
- 图谱、展示文件、专题文件、小题文件或题页有改动后，重新运行生成脚本。脚本有检查模式，生成结果与仓库不一致时报错，测试运行它，所以忘了重新生成会在测试中发现。
- 生成的页面带 `<meta name="generator" content="tools/build-knowledge-pages.mjs">`。脚本只删除带这个标记、但已不在图谱里的目录；节点 ID 对应的目录里有不是脚本生成的页面时报错，不覆盖。
- 以后数据存进数据库时，详情页改为服务端动态生成或前端读接口渲染；页面结构不变，只换数据来源。

### 8.3 页面内容

从上到下：

1. **页头：** “高中数学 / 知识图谱 / 知识点”（“知识图谱”链接到 `/knowledge/#节点 ID`）、名称、`summary`。
2. **关系：** 知识点列前提、后续、以它为核心依据的方法；方法列核心知识依据。都是链接到对应详情页的标签，没有连线的行不显示。
3. **图解：** 有 `sheet` 时把图解直接展示在页面里，不弹窗；有小题文件时，标题行右侧是“刷题 · 8 题”按钮。`explain.js` 的 `renderExplainer(root, id)` 与弹层共用渲染、样式表插入、公式渲染和 `mount`/清理；页面内的图解没有底部链接，`data-explain-open` 按钮改为跳到该节点的详情页。加载失败时显示“图解暂时打不开，请刷新后重试。”没有图解但有小题时，单独一节“刷题”放按钮。
4. **解题步骤（只有方法页）：** 每个用到这种方法的专题一块，专题名链接到专题页。第一格是各题 `_basis` 步骤的名称（`/2/` 里是“判断适用条件”），之后按专题文件的 `sequence` 排出知识点，用箭头连接，每个链接到知识点详情页；与知识地图上这一列相同。

### 8.4 与其他页面的分工

- **知识地图、知识图谱的面板：** 快速看说明和关系，有图解的可以“看图解”，再加“查看详情 →”。不列题号，不写题数。
- **图解弹层：** 练习页里看规律，底部不加链接；其他页面打开时底部只有“查看“…”的详情 →”。
- **专题目录页：** 组织题目和整题练习；方法分组的“图解”打开弹层；知识地图里点开卡片显示面板，再从面板进入详情页。
- **详情页：** 看懂和刷题。

### 8.5 生成脚本

`tools/build-knowledge-pages.mjs` 为每个节点写出一个完整页面，文字来源：

| 内容 | 来源 |
| --- | --- |
| 名称、种类、关系 | `graph.json` |
| 说明、有没有图解 | `display.json` |
| 方法的步骤顺序 | 专题文件的 `methods` |
| 方法步骤图第一格 | 题页 `practice-config` 中该路线第一步的 `title` |
| 小题 | `site/data/knowledge/drills/<节点 ID>.json` |

- 题页只在两处读取：方法步骤图第一格的名称，以及检查小题 `source` 指向的步骤存在。
- 详情页地址由脚本 `import` `site/assets/explain/links.js` 的 `detailHref` 生成，与页面脚本用的是同一个函数。

## 9. 第三层：个人图谱

### 9.1 第一阶段：练习覆盖（不改数据库）

浏览器读取本人学习标记（现有 `GET /api/learning/marks`）和专题文件中的逐题对应，按节点汇总：

| 汇总项 | 计算 |
| --- | --- |
| 练过 | 用到该节点的题目中，`practiced` 的题数 / 总题数 |
| 自评掌握 | 其中 `learning_status=mastered` 的题数 |
| 需再练 | 其中 `needs_review` 的题数 |

- **展示：** 节点外圈按“自评掌握、练过未自评、需再练、未练”分段着色，不单靠颜色区分；图例写明“按你完成的题目和自评汇总”，不出现“掌握度”。
- **可以接着练：** 列出有“需再练”题目的节点（直接链接到那些题）、刷题状态为“需再刷”的节点（链接到详情页），以及自己没练过、但前提节点都练过的节点。最后一项是学习空间“外缘”的覆盖版近似，文案写“可以接着练”，不写“你已经会了前提”。
- 游客看到课程图谱，详情面板里提示登录后显示个人情况。

### 9.2 刷题状态（随第 7.7 节实施）

每个有小题的节点，由本人做完的刷题（第 7.7 节）推导一个状态。读取时按规则现算，不建状态表，规则调整不需要迁移数据。

| 状态 | 条件 |
| --- | --- |
| 未刷 | 没有做完的一轮 |
| 需再刷 | 最近做完的一轮里，一次答对的题少于 80%（5 题少于 4 题） |
| 刷题通过 | 最近做完的一轮，一次答对不少于 80% |
| 稳定 | 最近一轮通过，并且另有一轮在不同日期（北京时间）也通过 |

- 比例按这一轮的实际题数算，题库不足 5 题时同样适用。题目升修订号不影响已有记录。
- “稳定”要求隔天再刷：同一天连刷两轮，第二轮多半还记得上一轮的答案。
- 最近一轮没通过，状态就回到“需再刷”，以前通过过也一样；面板里另写“曾经通过”。
- 状态只描述刷题结果，名称和图例写“按你的刷题结果”，不叫“掌握度”。方法节点的刷题练的是“判断能不能用这种方法”，整条路线能不能走通仍看整题练习。
- **展示：** 有小题的节点，外圈按刷题状态着色，不单靠颜色区分；整题的练过、自评（第 9.1 节）放在节点面板里。没有小题的节点仍按第 9.1 节显示覆盖。详情页的刷题按钮旁显示本人当前状态。
- 与步骤级证据（第 9.3 节）的关系：两者以后同时存在时，怎样合并成一个节点状态，到第 9.3 节落地时再定。刷题记录单独成表，届时不需要迁移。

### 9.3 第二阶段：步骤级证据（需要决定，见第 10 节）

记录每个步骤的完成情况，才能按知识点判断“会不会”，而不是按整题自评。建议的最小记录：

| 字段 | 含义 |
| --- | --- |
| `user_id`、`problem_id`、`route`、`node_id` | 哪个学生、哪道题、哪条路线、哪一步 |
| `run_id` | 一次从头练习的标识，与前三项一起保证重复提交只记一次 |
| `mode` | 练习方式：`whole` 整题、`drill` 刷题（第 7.6 节） |
| `attempts` | 完成前的错误提交次数 |
| `hint_level` | 用到的最强提示：无、步骤提示、AI 提示 |
| `ai_turns` | 本步骤 AI 对话轮数 |
| `tip_opened` | 本步骤完成前是否打开过图解 |
| `page_version`、`completed_at` | 题目版本与时间 |

不保存学生填写的内容和对话文本；对话文本仍按现有对话系统的规则保存。

节点状态按规则推导，首版不用概率模型：

| 状态 | 条件 |
| --- | --- |
| 未观察 | 没有对应步骤的记录 |
| 提示下完成 | 有记录，但每次都用了提示或错了再改 |
| 独立完成 | 至少一次首次即对、未用提示 |
| 跨题稳定 | 在至少两道不同的题里独立完成 |

方法节点的证据来自 `_basis` 步骤和整条路线的完成情况。系统代算的步骤、用了 AI 提示后才完成的步骤，都不计为独立完成（与学生交互系统设计的证据原则一致）。

### 9.4 第三阶段：推荐下一步

在刷题状态、第二阶段证据和经过审核的前提边之上，按学习空间文档的方法计算：学生状态取“跨题稳定”及以上、或刷题状态为“稳定”的节点，补成向下闭合的集合；外缘是前提都已具备的未掌握节点；与某道题需要的节点求差，推荐先补哪个知识点、去做哪道题。推荐必须能说明依据（缺哪个节点、哪道题会练到它）；推荐的练习可以是整题，也可以是缺的那个知识点的刷题。

数据测试（阶段 0 起），按文件分开：

- 连线语义人工审核：仅有证明路径或步骤共现不能建边；允许方法没有连线。
- `graph.json`：节点 `id` 唯一，重复知识按清单共用唯一 ID，`kind` 只有两种；`subtype: technique` 只用于方法节点；边的两端都存在；边类型仅 `uses`、`prerequisite`；`uses` 只从方法指向知识点；`prerequisite` 两端均为知识点、无自依赖且无环，且没有可由传递推出的多余边；方法之间无连线。
- 专题文件：
  - `nodes` 无重复，所有 ID 都在全局图谱里，不含独立节点定义或关系定义；
  - 方法、路线顺序及步骤引用的节点都在本专题的 `nodes` 范围内；
  - 同一 ID 在多个专题出现时仍只建一个节点；仅用于展示的前置节点不增加练习覆盖；
  - `problems` 的题目、路线、步骤与题页配置逐一对应，不多不少，空数组也要写；
  - `methods.route` 是题页里存在的路线，`_basis` 步骤对应该方法节点；
  - `sequence` 中的节点须在本专题范围内、在对应路线至少一道题中出现；不要求存在方法到它的全局 `uses` 边。
  - `examples` 的题目在本专题 `problems` 中，且有该方法的路线。
- `display.json`：键都是图谱里的节点；`sheet` 等于节点 `id`。
- 图解模块：`explain/knowledge/`、`explain/method/` 下的文件与有 `sheet` 的节点一一对应，目录与节点 `kind` 一致；每个文件有默认导出和 `render`，不发请求、不查询页面元素；`data-explain-open` 指向其他有图解的节点；独立样式表名为 `<节点 ID>.css`，选择器都以 `.explain-<节点 ID>` 开头。
- 调用方：`runtime.js`、`data.js`、专题目录页都经 `explain.js` 打开；目录页每个分组一个“图解”按钮，指向专题文件里该分组的第一个方法节点，顺序与专题文件一致；目录页不再有 `method-sheet`；目录页、图谱页配置的 `graph.json` 版本与 `explain.js` 一致，专题文件版本与 `links.js` 的 `TOPIC_URL` 一致。
- 题页 `tip`：分支 `{field, options}` 的字段是本路线到这一步为止的选择题，选项与该题的正确答案一一对应；展开后每条 `tip.id` 都在专题文件里该步骤的节点列表中，且 `display.json` 中该节点有 `sheet`；只含 `id`、`case`、`note`，`note` 以“本题”开头，`case` 是该图解认得的值；被指向的图解渲染 `problemNote(tip.note)`。
- 刷题（阶段 9 起）：小题文件由生成脚本按第 7.2 节校验；文件名与节点一致；页面嵌入的数据与文件一致（去掉 `source`），按钮写明题数；`source` 指向的步骤在专题文件里对应本节点；没有小题文件的节点页面不带刷题数据。阶段 11 起页面不再嵌入小题，改为检查页面里没有答案和反馈、导入后的数据库内容与文件一致。
